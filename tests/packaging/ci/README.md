# Packaging checks

These scripts check every supported way of getting GridFire and linking against it, on each platform wheels are
released for. They are run by [`.github/workflows/packaging.yml`](../../../.github/workflows/packaging.yml), and each one
can also be run by hand.

| Check | What it does |
|---|---|
| `wheel` | builds the wheel the way a release does: `auditwheel` on Linux, `delocate` with an LLVM libomp built for the deployment target on macOS. The fourdst libraries are excluded, and the check fails if a copy of them ends up in the wheel |
| `python-install` | installs the wheel into a fresh environment next to the pinned fourdst wheel; `import gridfire` and `gf-config` both have to work |
| `gf-config` | C++, C and Fortran programs ([`consumer.*`](..)) built with the flags `gf-config` prints, then run |
| `pkg-config` | the same programs built with the wheel's relocatable `.pc` files |
| `threads-libgomp` | [`gridfire_threads.c`](../../extern/C/gridfire_threads.c) built with GCC `-fopenmp` (libgomp, as DSEP is), running separate contexts concurrently from 8 and 16 threads; results must be bit-identical to a serial run |
| `cmake-find` | [`cmake_consumer`](../cmake_consumer) using `find_package(GridFire)` against the wheel |
| `cmake-fetch` | `cmake_consumer` using `FetchContent` to build GridFire from this source tree with Meson |
| `meson-subproject` | [`meson_consumer`](../meson_consumer) with a clean copy of this tree as its GridFire subproject; Meson downloads GridFire's own dependencies |

A check that cannot run because an earlier one failed (for example, everything after a failed `wheel`) is recorded as
skipped. Each script runs every check it can and records the outcome in `results-<platform>[-<job>].json`.
[`report.py`](report.py) combines those results into the platform-by-check table that appears in the run summary.
On pushes to `main`, the report job also publishes one [shields.io endpoint](https://shields.io/badges/endpoint-badge)
badge per platform and check to the `ci-status` branch, and the main README's "Packaging status" table shows those
badges. That table is generated by:

```bash
python3 tests/packaging/ci/report.py --readme-table 4D-STAR/GridFire ci-status
```

## Running locally

**Linux.** The checks run inside the manylinux image that release wheels are built in:

```bash
docker run --rm -v "$PWD:/io/src:ro" -v "$PWD/ci-out:/io/out" tboudreaux/manylinux_2_28_aarch64_boost_1_88_0 \
    bash /io/src/tests/packaging/ci/linux.sh wheel linux-aarch64
```

Replace `wheel` with `source` to run the FetchContent and Meson-subproject checks instead. Use the `x86_64` image on
x86_64 machines.

**macOS (Apple Silicon).** The checks run on the machine itself. Pass `LIBOMP_PREFIX` to reuse a libomp that is
already built; without it, the script builds one.

```bash
LIBOMP_PREFIX=$PWD/utils/wheels/libomp-15.0-19.1.7 tests/packaging/ci/macos.sh macos-arm64 ci-out
```

**The whole workflow, with [act](https://github.com/nektos/act).** `act` can run the Linux and report jobs. It skips
the macOS job because it has no macOS runner. Run it from a scratch clone, because `--bind` lets the jobs write into
the directory:

```bash
GITHUB_TOKEN= act workflow_dispatch -W .github/workflows/packaging.yml --matrix arch:aarch64 \
    -P ubuntu-24.04-arm=catthehacker/ubuntu:act-latest -P ubuntu-24.04=catthehacker/ubuntu:act-latest \
    --container-architecture linux/arm64 --bind --artifact-server-path /tmp/act-artifacts -s GITHUB_TOKEN=
```

- `--bind` is required, because the jobs start the manylinux container with `docker run -v`, which needs the
  workspace to be a real path on the host.
- `--matrix arch:aarch64` keeps to the native architecture on Apple Silicon. The x86_64 jobs would run under
  emulation.
- The empty `GITHUB_TOKEN` stops `act` from using a stale `gh` login token, which makes even public action clones
  fail.
- The badge publish step never runs under `act`.

Typical times, measured locally on Apple Silicon: about 13 minutes per Linux job, and about 10 minutes for macOS once
libomp is built (building libomp adds a few more). Most of that time goes into building GridFire.
